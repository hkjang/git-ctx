# git-ctx v0.68.1

이번 릴리스는 **콘솔이 운영자에게 하던 틀린 말**을 고치고, 콘솔 렌더링 검증을 내용이 있는 설치에서도 돌립니다. 기본 서비스 포트는 계속 `4747`이며 기존 API·MCP 호환성을 유지합니다.

## 수정

### 콘솔이 지키지 않아도 되는 제약을 지키라고 했습니다

지난 세 릴리스가 키 관리 방식을 바꿨는데 콘솔 문구는 그대로였습니다. 운영자가 화면에서 읽는 말은 문서만큼 중요합니다.

- "설정 암호화 키는 최초 Bootstrap DSN 에서 파생됩니다. Bootstrap DSN 문자열을 임의로 바꾸면 기존 설정을 복호화할 수 없습니다" — v0.66.0 부터 키는 데이터베이스에 저장되고 복구 키로 감싸입니다. DSN 은 자유롭게 바꿀 수 있으며, 지켜야 하는 것은 복구 키입니다.
- "백업은 Master Key 로 암호화되며" (백업 화면과 가이드 두 곳) — v0.67.0 부터 `GIT_CTX_RECOVERY_KEY` 에서 파생한 키로 봉인됩니다. **어떤 비밀을 지켜야 하는지를 잘못 알려 주고 있었고**, 같은 복구 키를 가진 새 설치에서 복원할 수 있다는 사실도 빠져 있었습니다.

## 개선

### 콘솔 렌더링 검증이 빈 설치에서만 돌고 있었습니다

- 브라우저 렌더 스윕은 모든 관리자 화면을 열어 빈 화면과 콘솔 오류를 잡습니다. 그런데 **언제나 빈 데이터베이스**를 상대로 돌았습니다 — 그릴 것이 아무것도 없는 단 하나의 상태에서만 모든 화면을 확인한 셈입니다.
- 저장소 5곳(GitLab·Bitbucket·Confluence·Jira), 색인된 청크·심볼·파일·패키지·저장소 지도, 성공·실패·실행 중·대기 중 색인 작업, 성공·오류·빈 결과·거부된 MCP 호출, 처리된·실패한 웹훅, 보안 이벤트, 알림, 감사 로그, 백업 기록을 채우는 시드를 추가했습니다.
- 스윕이 이제 **빈 설치와 내용이 있는 설치 두 번** 돕니다. 그리고 렌더된 텍스트에서 `undefined`·`NaN`·`[object Object]`·`Invalid Date` 를 찾아 실패시킵니다.

## 검증

- 시드된 설치에서 전체 화면 렌더링, 나쁜 토큰 없음
- 기록에 없는 백업 파일(v0.67.0 의 `discovered`)이 목록에 함께 그려지는지 브라우저로 확인
- FTS5 빌드·태그 없는 빌드·PostgreSQL 3가지 조합 전체 단위·통합·race 테스트, 빌드 모드 교차 시험, 릴리스 바이너리 업그레이드 시험

## 업그레이드 참고

- 마이그레이션이나 재색인은 필요하지 않습니다. 콘솔 문구와 시험만 바뀝니다.
