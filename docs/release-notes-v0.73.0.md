# git-ctx v0.73.0

이번 릴리스는 **이 버전이 읽지 않는 설정 항목을 조용히 삼키던 문제**를 고칩니다. 기본 서비스 포트는 계속 `4747`이며 기존 API·MCP 호환성을 유지합니다.

## 수정

### 오타 난 설정 항목이 "적용됨" 으로 답했습니다

- 설정은 이 빌드가 읽지 않는 항목도 보존합니다. 새 콘솔이 아직 배우지 않은 서버에 값을 저장할 수 있어야 하기 때문이며, 옳은 설계입니다.
- 그 앞뒤 호환성이 **평범한 실수를 가려 줬습니다.** 관측성 설정에 `enabled` 대신 `tracingEnabled` 를 보내면 추적은 **꺼진 채로** 저장되고, 응답은 `200`, `"applied": true` 입니다.
- 운영자는 성공을 보고 추적을 기다리지만 스팬은 영원히 오지 않습니다. 응답 어디에도 정작 중요한 항목이 읽히지 않았다는 말이 없습니다.
- 이제 응답이 **이 빌드가 읽지 않은 항목의 이름을 말합니다**. 값은 그대로 저장됩니다 — 보존은 그대로 두고, 조용함만 없앴습니다.

## 검증

- **OTLP 내보내기를 끝에서 끝까지 확인했습니다.** 설정을 저장하고 MCP 도구를 부르면 스팬이 실제로 수집기의 `/v1/traces` 에 도착합니다. 이 조사 중에 위 결함이 드러났습니다 — 첫 시도에서 `applied: true` 를 받고도 아무것도 오지 않았습니다.
- 평문 HTTP 엔드포인트는 `allowInsecureLocalhost` 를 명시해야 통과하며(설계대로), `enabled: true` 저장은 실제 내보내기 시험을 수행합니다.
- 오타 난 항목이 이름과 함께 보고되고, 그래도 저장되며, 정상 payload 에는 아무 말도 붙지 않는지 회귀 시험. 수정을 되돌리면 `accepted without a word` 로 실패합니다.
- **배경 워커와 경주하는 시험이 더 없는지 전수 점검**했습니다. 직전 릴리스에서 두 건을 고쳤고, 같은 모양(배경이 소유한 표를 `waitFor` 없이 세는 시험)은 그 하나뿐이었음을 확인했습니다.
- FTS5 빌드·태그 없는 빌드·PostgreSQL 3가지 조합 전체 단위·통합·race 테스트, 빌드 모드 교차 시험

## 업그레이드 참고

- 마이그레이션이나 재색인은 필요하지 않습니다.
- 설정 저장 응답에 `ignoredFields` 와 경고가 추가될 수 있습니다. 저장 동작 자체는 바뀌지 않습니다.
