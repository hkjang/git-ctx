# git-ctx v0.53.7

이번 릴리스는 웹훅 수신기의 **응답 코드**를 바로잡습니다. 기본 서비스 포트는 계속 `4747`이며 기존 API·MCP 호환성을 유지합니다.

## 수정

- **이 플랫폼 쪽 장애가 “거절”로 응답되고 있었습니다.** 데이터베이스가 응답하지 못해 이벤트를 기록하지 못한 경우에도 `404` 를 돌려주었고, 소스 서버는 4xx 를 재시도하지 않으므로 그 push 이벤트는 그대로 사라졌습니다. 이제 이런 경우 `500` 으로 답해 소스 서버가 재시도합니다.
- **읽을 수 없는 payload 와 미등록 저장소가 같은 코드였습니다.** 둘 다 `404` 였는데, 앞은 보낸 쪽이 고쳐야 하고 뒤는 운영자가 저장소를 등록해야 하는 서로 다른 문제입니다. 이제 payload 오류는 `400`, 미등록 저장소는 `404` 입니다.
- 소스가 아예 설정되지 않은 경우만 `503 webhook_not_configured` 로 남습니다. 설정을 읽다가 실패한 경우는 “설정되지 않았다”가 아니라 재시도 대상으로 응답합니다.

## 검증

- 실제 인스턴스에서 GitLab 웹훅을 직접 호출해 확인했습니다.
  - 서명 불일치 `401`, 읽을 수 없는 payload `400`, 미등록 저장소 `404`, 미설정 소스 `503`
  - 정상 push `202` 와 색인 작업 1건 등록, 동일 이벤트 재전송 `200` + `duplicate: true`
  - 거절된 이벤트는 사유와 함께 수신 현황 화면에 기록
- 저장소가 응답하지 않을 때 재시도 가능한 상태 코드가 나가는지 회귀 시험
- Go 전체 단위·통합·race 테스트, vet와 build

## 업그레이드 참고

- 마이그레이션이나 재색인은 필요하지 않습니다.
- 웹훅 모니터링에서 오류 코드를 기준으로 알림을 걸어 두었다면, 잘못된 payload가 `400` 으로 바뀌는 점을 반영하세요.
