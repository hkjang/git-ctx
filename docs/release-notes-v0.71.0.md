# git-ctx v0.71.0

이번 릴리스는 **재전송된 웹훅이 아무 흔적도 남기지 않던 문제**를 고칩니다. 기본 서비스 포트는 계속 `4747`이며 기존 API·MCP 호환성을 유지합니다.

## 수정

### 같은 내용으로 다시 도착한 훅이 통째로 사라졌습니다

- 한 저장소·한 이벤트 종류에 대해 내용이 같은 payload 는 **의도적으로** 중복 제거됩니다. 소스 서버가 시간 초과로 판단해 훅을 재전송하는 것이 이 경로가 있는 이유이고, 같은 푸시를 두 번 색인하는 것은 낭비입니다.
- 그런데 중복은 **흔적 없이 버려졌습니다** — 행도, 카운터도, 상태도 없습니다. 이벤트 id 가 새것이어도 마찬가지입니다.
- 그래서 "푸시는 됐는데 왜 색인이 안 되지" 를 묻는 운영자는 **아무것도 도착하지 않은 화면**을 보게 됩니다. 훅이 정상 동작 중인지, 아예 오지 않는지 구분할 방법이 없었습니다.
- 거부 경로에는 이미 그 이유가 주석으로 적혀 있습니다 — "조용히 버리는 것이 잘못 향한 훅을 보이지 않게 만들었다". 중복 경로에만 그 원칙이 적용되지 않았습니다.
- 이제 원래 이벤트의 재전송 횟수와 마지막 도착 시각을 기록합니다. 관리자 화면의 웹훅 요약에 `재전송 N건` 이 표시되고, 해당 이벤트 줄에 "같은 내용으로 N번 다시 도착했습니다 (마지막 …). 재색인하지 않았습니다." 가 나옵니다.

## 검증

- **적대적 입력으로 웹훅 엔드포인트를 직접 두드렸습니다.** 서명 없음·틀린 서명·비밀의 접두사·모르는 저장소·깨진 payload·2MB 초과·소스 교차 비밀 — 전부 올바르게 거부합니다(401/404/400/503).
- Bitbucket 의 HMAC 경로: 본문을 변조하면 **같은 서명이 401 로 거부**되고, 대문자 16진수와 `sha256=` 접두사 유무는 모두 정상 처리됩니다.
- 재전송이 카운트되고 색인 작업은 하나만 생기는지 회귀 시험. 수정을 되돌리면 `records 0` 으로 실패합니다.
- FTS5 빌드·태그 없는 빌드·PostgreSQL 3가지 조합 전체 단위·통합·race 테스트, 빌드 모드 교차 시험, 릴리스 바이너리 업그레이드 시험, 콘솔 시험

## 업그레이드 참고

- 마이그레이션 `049_webhook_duplicates.sql` 이 추가됩니다. 자동 적용됩니다.
- 중복 제거 동작 자체는 바뀌지 않습니다. 재전송이 이제 기록될 뿐입니다.
