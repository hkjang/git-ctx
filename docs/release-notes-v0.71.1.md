# git-ctx v0.71.1

이번 릴리스는 **복제본 두 개가 한 데이터베이스를 나눠 쓰는 배포**를 실제로 검증하고, 잡을 어느 인스턴스가 쥐고 있는지 기록합니다. 기본 서비스 포트는 계속 `4747`이며 기존 API·MCP 호환성을 유지합니다.

## 검증

- 배포 매니페스트는 `replicas: 2` 를 선언합니다. 두 인스턴스가 같은 잡 큐를 폴링하는데, **둘을 함께 돌려 본 적이 없었습니다.**
- 클레임이 원자적이지 않으면 저장소가 두 번 색인되어 청크·심볼·의존 행이 전부 두 배가 되거나, 두 워커가 서로 자기 것이라 믿어 하나가 다른 하나의 결과를 덮어씁니다. **둘 다 단일 프로세스 시험에는 나타나지 않습니다.**
- PostgreSQL 한 곳에 인스턴스 둘을 붙이고 저장소 6곳을 등록해 확인했습니다: 중복 색인 없음, 잡별 시도 1회, 완료 6건.
- **경쟁이 실제로 일어났는지도 확인합니다.** 한 복제본이 전부 처리했다면 exactly-once 는 아무것도 증명하지 못합니다. 시험은 잡을 복제본별로 세어 둘 다 참여하지 않았으면 그 사실을 보고합니다 — 실측은 `first:3 second:3` 이었습니다.
- 클레임 구현 자체는 올바릅니다. PostgreSQL 은 `FOR UPDATE SKIP LOCKED` 로 잡고 UPDATE 에 `status='pending'` 가드를 겁니다.

## 개선

### 잡을 누가 쥐고 있는지 기록하지 않았습니다

- `running` 상태의 잡은 **언제** 시작했는지는 말하지만 **어디서** 인지는 말하지 않았습니다. 파드 둘에 멈춘 저장소 하나가 있는 운영자가 어느 파드를 봐야 하는지 알 수 없었습니다.
- 리스 만료 메시지도 `worker lease expired` 뿐이라 **누구의 리스였는지** 말하지 않았습니다.
- 이제 워커가 호스트·PID·임의 접미사로 자기를 이름 짓고, 클레임에 기록합니다. `list-index-jobs` 가 `Claimed by:` 로 보여 주고, 리스 만료 메시지가 그 이름을 담습니다.

## 검증(계속)

- FTS5 빌드·태그 없는 빌드·PostgreSQL 3가지 조합 전체 단위·통합·race 테스트, 빌드 모드 교차 시험, 릴리스 바이너리 업그레이드 시험
