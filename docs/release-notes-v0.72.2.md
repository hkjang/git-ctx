# git-ctx v0.72.2

**v0.72.1 은 발행되지 않았습니다.** 시험 두 개가 CI 에서 실패해 릴리스 워크플로가 중단됐고, 자산이 만들어지지 않았습니다. 이 릴리스가 그 수정과 v0.72.1 의 내용을 함께 담습니다. 기본 서비스 포트는 계속 `4747`이며 기존 API·MCP 호환성을 유지합니다.

## 수정: 배경 워커와 경주하던 시험 두 개

두 실패 모두 같은 원인이었습니다 — **살아 있는 워커가 큐를 비우는 동안 큐의 상태를 세는** 시험입니다. 지역에서는 통과하고 CI 의 타이밍에서만 드러납니다.

- `TestSavingAnIndexPolicyQueuesTheRebuild` 는 `status='pending'` 인 잡을 세어 2를 기대했습니다. 워커가 2초마다 하나를 가져가므로, 그중 하나가 이미 `running` 이면 1이 나옵니다. 확인하려는 것은 "정책 저장이 두 ref 의 재빌드를 큐에 넣었는가" 이고, 그것은 워커가 시작했든 아니든 참입니다. 상태와 무관하게 셉니다.
- `TestTwoReplicasIndexEachJobOnceIntegration`(v0.71.1 에서 제가 추가) 은 완료된 잡 수가 등록 수와 같기를 요구했습니다. 스케줄러가 폴링 주기가 돌아온 저장소에 **자기 새로고침 잡**을 넣으므로, 그중 하나가 창 안에 들어오면 7 대 6 이 됩니다. 저장소가 두 번 색인된 것과는 다르며, 그것은 중복 행 검사가 이미 배제합니다. 이제 "모든 저장소가 완료된 잡을 갖는가" 를 확인합니다.

두 시험 모두 지키려던 성질은 그대로입니다 — 정책 저장이 재빌드를 큐에 넣는다, 잡은 한 번만 클레임된다, 복제본 둘이 실제로 경쟁한다.

## v0.72.1 에서 가져온 수정

### query-docs 가 매치 없음을 실패로 보고했습니다

- `query-docs` 는 색인에 히트가 없으면 소스 코드 검색으로 한 번 더 시도합니다. 그 대체 시도가 실패하면 **호출 전체를 오류로** 돌려줬습니다.
- 커넥터가 아직 설정되지 않았거나 일시 정지된 설치에서는, 표현이 색인과 맞지 않았을 뿐인 질의가 `isError: true` 로 돌아옵니다. 에이전트는 도구가 고장난 줄 알고 다르게 물어보는 대신 재시도하거나 포기합니다.
- 이제 정상 답변으로 **두 사실을 다 말합니다**: 색인에 매치가 없었다는 것과, 라이브 검색은 시도되지 않았고 그 이유.
- **소스가 거절했거나 깨진 경우는 그대로 오류입니다.** 폐기된 토큰(401)이나 검색 불가 ref 는 운영자가 고쳐야 할 문제입니다.

## 검증

- 저장소의 k6 부하 스크립트가 주장하는 부하를 직접 걸어 확인했습니다(실측: 동시 50 에서 실패 0, `search-code` p95 586ms, 임계 p95<3s).
- 두 시험을 반복 실행해 안정적으로 통과함을 확인
- CI 통합 잡과 같은 명령(`go test -run Integration`)을 그대로 실행
- FTS5 빌드·태그 없는 빌드·PostgreSQL 3가지 조합 전체 단위·통합·race 테스트, 빌드 모드 교차 시험

## 업그레이드 참고

- 마이그레이션이나 재색인은 필요하지 않습니다.
- 커넥터가 없는 설치에서 `query-docs` 가 오류 대신 답을 돌려줍니다.
