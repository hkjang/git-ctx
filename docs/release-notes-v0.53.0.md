# git-ctx v0.53.0

이번 릴리스는 **웹훅 수신 가시성**을 추가합니다. 기본 서비스 포트는 계속 `4747`이며 기존 API·MCP 호환성을 유지합니다.

## 주요 개선

- `GET /api/v1/admin/webhook-events` 와 소스·색인 화면의 **웹훅 수신** 카드를 추가했습니다. 소스 서버가 실제로 보낸 이벤트와 최근 7일 요약(수신·색인 예약·거부)을 보여 줍니다.
- **거부된 이벤트를 사유와 함께 기록합니다.** 이전에는 등록되지 않은 저장소를 가리키는 훅이 404 만 남기고 사라져, 운영자에게는 "웹훅을 걸었는데 색인이 안 된다"는 증상만 보였습니다. 이제 `rejected` 로 남고, **보낸 쪽이 사용한 저장소 식별자**가 함께 표시되어 어느 저장소를 등록해야 하는지 바로 알 수 있습니다.
- 파싱할 수 없는 페이로드도 같은 방식으로 기록합니다.
- 서명 검증에 실패한 요청은 기록하지 않습니다. 인증되지 않은 요청은 임의의 외부 요청이므로 남기는 것 자체가 저장소 낭비입니다.

자동 색인이 되지 않을 때의 세 가지 원인 — 훅 미설정, 다른 저장소를 가리키는 훅, 색인 실패 — 가운데 앞의 둘이 이제 화면에서 구분됩니다. 색인 실패는 기존 색인 진단이 답합니다.

## 감사 결과 (수정 없음)

- 웹훅 인증 경로를 감사했습니다. Bitbucket 은 HMAC-SHA256 서명을, GitLab 은 토큰을 각각 상수 시간으로 비교하고, 비밀값이 없으면 수신을 거부하며, 본문은 2MB 로 제한되고, 이벤트 ID 가 없으면 페이로드 해시로 중복을 판별합니다. 변경할 결함은 없었습니다.

## 업그레이드 참고

- 마이그레이션 `045_webhook_visibility.sql` 이 `webhook_events` 에 사유 컬럼과 수신 시각 인덱스를 추가합니다. 기존 행은 그대로 유지됩니다.
- 보존 기간은 기존 운영 설정의 웹훅 이벤트 보존일을 그대로 따릅니다.

## 오프라인 Docker 이미지

릴리스 자산은 아키텍처 접미사가 없는 다음 두 파일입니다.

- `git-ctx-v0.53.0.tar.gz`
- `git-ctx-v0.53.0.tar.gz.sha256`

```bash
sha256sum -c git-ctx-v0.53.0.tar.gz.sha256
gzip -dc git-ctx-v0.53.0.tar.gz | docker load
docker image inspect git-ctx:v0.53.0 --format '{{.Os}}/{{.Architecture}} {{.Config.User}}'
```

기대 결과는 `linux/amd64 10001`입니다. 아카이브에는 `git-ctx:v0.53.0`과 `git-ctx:0.53.0` 태그가 포함됩니다.

## 검증

- Go 전체 단위·통합·race 테스트, vet와 build
- 웹훅 거부 기록 시험: 미등록 저장소는 사유와 식별자를 남기고, 파싱 실패도 기록되며, 거부는 색인 작업을 만들지 않고, 저장소 등록 후 같은 훅이 정상 수신됨
- 관리자·사용자 UI JavaScript 구문 및 계약 시험
