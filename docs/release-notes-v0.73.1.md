# git-ctx v0.73.1

이번 릴리스는 직전 릴리스가 시작한 것을 **모델 설정까지** 넓히고, 그 과정에서 드러난 저장소 자신의 잘못된 예시를 정리합니다. 기본 서비스 포트는 계속 `4747`이며 기존 API·MCP 호환성을 유지합니다.

## 개선

### 모델 설정도 읽지 않은 항목을 알려 줍니다

- v0.73.0 은 관측성·로깅 범주에서 이 빌드가 읽지 않은 항목의 이름을 응답에 담게 했습니다. 같은 노출이 다른 범주에도 있습니다.
- 모델 범주를 추가했습니다. 목록은 **코드에서 유도**했습니다 — `embeddingProviderFromMap`, `rerankerProvider`, `searchConfig` 가 실제로 읽는 키만 담았고, 짐작으로 넣은 항목은 없습니다.
- 나머지 범주는 아직 넣지 않았습니다. 그 키 목록이 한곳에 없어 손으로 만들면 **정상 필드를 오탐할** 위험이 크고, 잘못된 경고는 없는 경고보다 나쁩니다.

### 저장소 자신의 시험이 잘못된 예시를 보내고 있었습니다

- 모델 설정에 `dimensions` 를 보내던 payload 7곳을 정리했습니다. **차원은 벡터 저장소 설정**이고 모델 범주는 그 항목을 읽지 않습니다 — 제공자에게 전달되지도 않습니다.
- 새 경고가 바로 그것을 잡아냈습니다.

## 검증

- **유지보수 모드를 실제로 확인했습니다.** 켜면 `/mcp` 가 운영자가 적은 메시지와 함께 503 을 돌려주고, `readyz` 와 관리자 경로는 열린 채로 남습니다. 웹훅을 계속 받는 것도 옳습니다 — 거부하면 소스 서버가 재시도 예산을 소진해 이벤트를 잃습니다.
- **임베딩 차원이 어긋날 때 무슨 일이 생기는지 확인했습니다.** 길이가 다른 벡터의 코사인은 0을 돌려주므로 잘못된 점수나 패닉은 없습니다. 모델을 바꾸면 `Identity()` 가 달라져 기존의 재색인 장치가 동작합니다.
- 모델 범주의 잘못된 항목이 이름과 함께 보고되는지 회귀 시험
- FTS5 빌드·태그 없는 빌드·PostgreSQL 3가지 조합 전체 단위·통합·race 테스트, 빌드 모드 교차 시험, 콘솔 시험

## 업그레이드 참고

- 마이그레이션이나 재색인은 필요하지 않습니다.
- 모델 설정 저장 응답에 `ignoredFields` 가 붙을 수 있습니다. 값은 이전처럼 그대로 저장됩니다.
