# git-ctx v0.53.2

이번 릴리스는 **pnpm 락파일을 읽지 못하던 결함**을 고칩니다. 기본 서비스 포트는 계속 `4747`이며 기존 API·MCP 호환성을 유지합니다.

## 수정

- **pnpm v5·v6·v7 락파일이 전혀 파싱되지 않았습니다.** 이 형식들은 `/lodash/4.17.21:` 처럼 슬래시로 이름과 버전을 구분하는데, 파서는 v9 의 `lodash@4.17.21:` 형식만 알고 있었습니다. 해당 저장소는 **인벤토리에서 조용히 빠져** 보안 공지 조회에서 "사용처 없음" 으로 보였습니다. 세 형식을 모두 읽습니다.
- **v9 의 scope 패키지(`@babel/core`)도 누락됐습니다.** 이름에 `/` 가 들어가는 경우를 이름 패턴이 받아들이지 않았습니다.
- **peer 해석 접미사**(`/react-dom/18.2.0(react@18.2.0):`)를 버전의 일부로 읽던 문제를 고쳤습니다. 접미사는 해석 맥락이지 버전이 아닙니다.

조용한 누락은 이 기능이 막으려던 실패 방식 그 자체입니다. 읽지 못하는 형식이 있으면 그 저장소만 통째로 빠지고, 남는 답은 "영향 없음" 이라는 잘못된 안심입니다.

## 감사 결과 (수정 없음)

- yarn 클래식과 yarn berry 두 형식을 모두 확인했고, 이름과 버전을 정확히 읽고 있어 변경이 필요 없었습니다. 회귀 시험으로 고정했습니다.

## 업그레이드 참고

- 마이그레이션은 필요하지 않습니다.
- **pnpm 을 쓰는 저장소는 재색인해야 인벤토리에 반영됩니다.** 소스·색인 화면의 의존성 인벤토리 커버리지로 확인하세요.

## 오프라인 Docker 이미지

릴리스 자산은 아키텍처 접미사가 없는 다음 두 파일입니다.

- `git-ctx-v0.53.2.tar.gz`
- `git-ctx-v0.53.2.tar.gz.sha256`

```bash
sha256sum -c git-ctx-v0.53.2.tar.gz.sha256
gzip -dc git-ctx-v0.53.2.tar.gz | docker load
docker image inspect git-ctx:v0.53.2 --format '{{.Os}}/{{.Architecture}} {{.Config.User}}'
```

기대 결과는 `linux/amd64 10001`입니다. 아카이브에는 `git-ctx:v0.53.2`와 `git-ctx:0.53.2` 태그가 포함됩니다.
