# git-ctx v0.52.4

이번 릴리스는 의존성 인벤토리가 **락파일의 해석된 버전**을 읽어, 지난 릴리스가 "판정 불가"로 남기던 경우를 실제로 판정합니다. 기본 서비스 포트는 계속 `4747`이며 기존 API·MCP 호환성을 유지합니다.

## 주요 개선

- 락파일을 인벤토리에 포함합니다: `go.sum`, `package-lock.json`(v1·v2·v3), `npm-shrinkwrap.json`, `yarn.lock`, `pnpm-lock.yaml`, `Cargo.lock`, `poetry.lock`.
- 매니페스트는 **의도**(`^18.2.0`)를, 락파일은 **결과**(`18.3.1`)를 말합니다. 보안 공지 판정은 락파일이 있으면 그쪽으로 결정하고, 진단에 "락파일에 해석된 버전으로 판정"을 명시합니다. 선언된 범위는 목록에 그대로 남습니다 — 고칠 때 편집하는 것은 그쪽이기 때문입니다.
- 락파일의 **중첩 사본**(같은 패키지의 다른 버전)을 각각 기록합니다. 취약한 전이 사본이 최상위 선언과 별개로 존재할 수 있고, 공지 대응에서 놓치면 안 되는 쪽이 보통 그쪽입니다.

## 수정

- **범위 선언의 판정 방향을 바로잡았습니다.** 범위는 위로만 해석되므로 `^18.2.0`처럼 하한이 수정 버전보다 낮은 경우 실제 해석 결과에 달려 있어 **판정 불가**입니다. 이전에는 하한만 보고 "영향"으로 단정해, 이미 패치된 저장소까지 영향 목록에 올렸습니다. 하한이 수정 버전 이상인 `>=2.17.1`은 그대로 안전으로 판정합니다. 정확히 고정된 버전만 영향으로 보고합니다.

## 업그레이드 참고

- 마이그레이션 `044_resolved_versions.sql`이 인벤토리 테이블을 **재작성합니다.** 락파일에서는 같은 패키지가 서로 다른 버전으로 두 번 나올 수 있어 기본키에 버전이 필요하기 때문입니다.
- **기존 인벤토리 행은 이전되지 않습니다.** 인벤토리는 색인에서 파생되는 데이터이고, 락파일을 읽으려면 어차피 재색인이 필요합니다. 재색인 전까지는 소스·색인 화면의 커버리지가 0으로 표시되므로 비어 있다는 사실이 드러납니다.
- 저장소를 재색인하면 매니페스트와 락파일이 함께 적재됩니다.

## 오프라인 Docker 이미지

릴리스 자산은 아키텍처 접미사가 없는 다음 두 파일입니다.

- `git-ctx-v0.52.4.tar.gz`
- `git-ctx-v0.52.4.tar.gz.sha256`

```bash
sha256sum -c git-ctx-v0.52.4.tar.gz.sha256
gzip -dc git-ctx-v0.52.4.tar.gz | docker load
docker image inspect git-ctx:v0.52.4 --format '{{.Os}}/{{.Architecture}} {{.Config.User}}'
```

기대 결과는 `linux/amd64 10001`입니다. 아카이브에는 `git-ctx:v0.52.4`와 `git-ctx:0.52.4` 태그가 포함됩니다.

## 검증

- Go 전체 단위·통합·race 테스트, vet와 build
- 락파일 파서 시험: go.sum 중복 제거, package-lock v1·v3, yarn.lock, Cargo.lock, poetry.lock, 중첩 사본 보존, 크기·개수 상한
- 판정 시험: 락파일이 있는 저장소는 해석된 버전으로, 없는 저장소는 판정 불가로. 락파일이 영향 버전이면 범위보다 우선
- 범위 방향 시험: 캐럿·틸드·`>=` 하한이 수정 버전 미만이면 판정 불가, 이상이면 안전, 정확한 고정만 영향
- 관리자·사용자 UI JavaScript 구문 및 계약 시험
