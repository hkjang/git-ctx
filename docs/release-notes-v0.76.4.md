# git-ctx v0.76.4

이번 릴리스는 **같은 파일이 도구에 따라 다른 커밋으로 인용되던 문제**를 고칩니다. 기본 서비스 포트는 계속 `4747`이며 기존 API·MCP 호환성을 유지합니다.

## 수정

### 한 파일, 한 ref, 그런데 인용 커밋이 둘이었습니다

- 증분 색인 패스에는 **바뀐 파일만** 전달됩니다. 그래서 나머지 `repository_files` 행은 **처음 본 커밋을 그대로** 들고 있었습니다.
- 그런데 같은 파일의 청크는 새 커밋으로 다시 찍힙니다.
- `repository_files.commit_id`는 **`read-file`이 에이전트에게 주는 인용 커밋**입니다. 결과적으로 한 데이터베이스가 같은 경로에 대해:
  - `read-file` → `@c1`
  - `search-code` → `@c2`
  를 답했습니다. **내용이 전혀 바뀌지 않은 파일에 대해서 말입니다.**
- 증분 패스가 여러 번 쌓이면, 하나의 ref 안에서 인용 커밋이 **여러 시점으로 흩어집니다.** 답변 안의 인용을 비교하는 에이전트는 서로 다른 스냅샷에서 온 것으로 읽게 됩니다.
- 파일 목록은 "이 파일이 마지막으로 바뀐 때"가 아니라 **"이 ref"**를 서술합니다. 이제 그 ref의 모든 경로에 대해 그렇게 말합니다.
- 이 컬럼을 읽는 곳은 `read-file`의 인용 한 곳뿐이므로 다른 동작은 바뀌지 않습니다.

### 어떻게 찾았는가

- **증분 패스로 도달한 데이터베이스**와 **같은 트리를 처음부터 색인한 데이터베이스**를 색인이 쓰는 모든 테이블에 대해 행 단위로 비교했습니다.
- 각각에는 자기 시험이 있었지만, **둘이 일치해야 한다고 요구한 것은 없었습니다.** 그리고 일치하지 않았습니다.
- 이 비교는 이제 시험입니다. 그리고 **두 데이터베이스에서 모두 비어 있는 테이블이 있으면 실패합니다** — 아무것도 없는 것에 대한 일치는 일치가 아닙니다. 실제로 이 시험의 첫 판이 심볼과 의존성에 대해 정확히 그랬고, 픽스처에 진짜 내용을 넣고 나서야 차이가 드러났습니다.

## 검증

- `document_chunks`·`code_symbols`·`code_dependencies`·`repository_files`·`repository_packages`·`repository_maps`·`repository_ref_states` 일곱 테이블을 행 단위로 비교
- 삭제·추가·수정·매니페스트 삭제·심볼 제거·의존성 제거가 모두 포함된 변경 집합으로 확인
- 같은 데이터베이스 안에서 `repository_files.commit_id`와 `document_chunks.commit_id`가 파일마다 일치하는지 확인하고, 비교한 파일이 3개 미만이면 실패
- 수정을 되돌리면 `docs/stays.md is cited as @c1 by read-file and @c2 by search-code`로 실패합니다
- FTS5 빌드·태그 없는 빌드·PostgreSQL 3가지 조합 전체 단위·통합·race 테스트, 빌드 모드 교차 시험, 릴리스 데이터베이스 업그레이드 시험, 콘솔 시험

## 업그레이드 참고

- 마이그레이션이나 재색인은 필요하지 않습니다.
- **이미 흩어진 인용 커밋은 다음 색인 패스에서 정리됩니다.** 커밋이 움직이지 않은 저장소도 다음 정기 폴링에서 갱신됩니다.
- 인용이 가리키던 커밋의 내용 자체는 정확했습니다 — 바뀌지 않은 파일이므로 `@c1`과 `@c2`의 내용이 같습니다. 바뀐 것은 **한 플랫폼이 하나의 스냅샷을 말하게 됐다**는 점입니다.
