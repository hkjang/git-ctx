# git-ctx v0.59.0

이번 릴리스는 **한 소스가 답했다는 이유로 다른 소스의 내용이 가려지던 문제**를 고칩니다. 기본 서비스 포트는 계속 `4747`이며 기존 API·MCP 호환성을 유지합니다.

## 수정

- `search-code` 는 실시간 소스 질의가 **아무것도 돌려주지 못했을 때만** 색인을 봤습니다. 카탈로그에 여러 소스가 있고 그중 일부만 실시간 질의에 답한다는 사실이 빠져 있었습니다 — **Confluence 페이지와 Jira 이슈는 색인에만 존재합니다.**
- 그래서 이슈 트래커가 질의와 무관한 결과 두 건을 돌려주면, 실제로 그 문구를 담고 있는 위키 페이지는 답에서 사라졌습니다. Git 서버·위키·이슈 트래커를 함께 연결한 상태에서 실측으로 확인했습니다.
- 이제 실시간 결과가 요청한 개수를 채우지 못하면 **항상 색인을 함께 봅니다.** 실시간 결과가 앞자리를 지키고(그쪽이 더 최신입니다), 색인에서 온 항목은 중복 없이 뒤에 붙으며, 몇 건이 색인에서 왔는지 답에 밝힙니다.

## 추가

- `TestDocumentSourceChainIntegration` — Confluence 와 Jira 를 같은 프로세스에 세우고 설정 저장 → 등록 → 색인 → 검색까지 확인합니다.

```text
ACL        커넥터가 선언한 principal 이 저장소 ACL 로 들어옴(이 소스에는 페이지별 권한이 없음)
본문       Confluence 저장 형식(마크업)이 아니라 텍스트로 색인됨
검색       위키 페이지와 이슈가 각각 검색됨
```

- 이전 동작(실시간 결과가 있으면 색인을 보지 않음)으로 되돌리면 위키 페이지를 찾지 못해 실패하는 것을 확인했습니다.

## 검증

- FTS5 빌드·태그 없는 빌드 양쪽 전체 단위·통합·race 테스트
- 체인 시험 6종, 콘솔 렌더 스윕 포함

## 업그레이드 참고

- 마이그레이션이나 재색인은 필요하지 않습니다.
- 실시간 소스가 답하는 질의에도 색인 결과가 함께 나올 수 있습니다. 답에 `index:` 진단이 붙으면 그 항목들은 마지막 색인 시점 기준입니다.
