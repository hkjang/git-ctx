# git-ctx v0.76.0

이번 릴리스는 **거절된 API 키가 아무 흔적도 남기지 않던 문제**를 고칩니다. 기본 서비스 포트는 계속 `4747`이며 기존 API·MCP 호환성을 유지합니다.

## 보안 관측성

### 거절된 API 키가 어디에도 남지 않았습니다

- Bootstrap 로그인과 복구 로그인의 실패는 감사 로그에 기록됩니다. 그런데 **MCP 클라이언트가 실제로 제시하는 자격증명**인 API 키의 거절은 기록되지 않았습니다.
- 감사 로그에도, 알림에도, 어디에도 없었습니다. "누군가 우리가 발급한 적 없는 키로 MCP 엔드포인트를 두드리고 있는가"라는 질문에 **답할 방법이 없었습니다.** 모든 접근이 설명되는 것을 전제로 하는 플랫폼에서 이상한 공백입니다.
- 시도마다 한 줄을 쓰는 것이 이것이 빠져 있던 이유입니다. 자격증명 절도기의 주석이 그렇게 적고 있습니다 — 절도되지 않는 엔드포인트는 감사 로그를 채웁니다. 같은 문제가 반대 방향을 가리킬 뿐입니다.

### 그래서 시간이 아니라 횟수로 간격을 둡니다

- 한 주소의 **첫 번째** 거절을 기록하고, 그다음 **열 번째**, **백 번째**, **천 번째**를 기록합니다.
- 한 번의 탐색은 즉시 보이고, 대량 탐색은 시간당 네 줄이면 끝나며, 각 줄이 **그 시점까지 몇 번의 시도를 대표하는지** 담습니다.
- 거절된 키는 Bootstrap·복구 엔드포인트와 **별도로** 셉니다. 한쪽의 홍수가 다른 쪽을 지키는 예산을 소진하면 안 됩니다.

### 무엇을 기록하고 무엇을 기록하지 않는가

- 기록하는 것: 키의 **prefix** — `api_keys` 테이블이 저장하는 것과 같은 값이라, 운영자가 자기 만료 키를 그대로 조회할 수 있습니다.
- 기록하지 않는 것: 키의 나머지 절반. 모르는 자격증명의 비밀 부분이 관리자가 읽을 수 있는 테이블에 들어가지 않습니다.
- API 키가 아닌 Bearer 토큰은 애초에 이 경로에 오지 않으며, 거절된 키로 기록되지도 않습니다.
- **할당량 초과는 거절된 자격증명이 아닙니다.** 여기에 기록하지 않습니다 — 바쁜 에이전트가 침입자로 보이면 안 됩니다.

## 수정

### 할당량에 걸린 호출이 언제 풀리는지 듣지 못했습니다

- 재시도 시각은 `Retry-After` 헤더에만 있었습니다. 호출자가 그 헤더를 실패 메시지에 담아 보여 준다는 보장은 없습니다.
- 본문에도 적습니다. `try again`이 있던 자리에 `try again in 47 seconds`를 놓는 데 드는 비용은 없습니다.

## 검증

- 첫 거절이 정확히 한 줄을 남기는지, 그 줄이 prefix를 담고 비밀 부분을 담지 않는지, 시도 수를 담는지 확인
- 100회 거절이 정확히 **세 줄**(1·10·100)을 남기는지, 마지막 줄이 누적 횟수를 담는지 확인
- API 키가 아닌 Bearer 토큰이 거절된 키로 기록되지 않는지 확인
- 할당량 초과 응답이 재설정 시각을 본문에 담는지, 그리고 **거절된 키로 감사되지 않는지** 확인 — 이 경로에는 앱 단위 시험이 아예 없었습니다
- 두 수정 모두 되돌리면 시험이 실패합니다
- FTS5 빌드·태그 없는 빌드·PostgreSQL 3가지 조합 전체 단위·통합·race 테스트, 빌드 모드 교차 시험, 릴리스 데이터베이스 업그레이드 시험, 콘솔 시험

## 업그레이드 참고

- 마이그레이션이나 재색인은 필요하지 않습니다.
- 감사 로그에 `apikey.auth` / `failure` 항목이 새로 나타납니다. 기존 보존 정책(`AuditLogDays`)이 그대로 적용됩니다.
- 성공하는 호출의 동작은 바뀌지 않습니다.
