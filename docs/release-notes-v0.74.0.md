# git-ctx v0.74.0

이번 릴리스는 **잘린 답이 요청한 예산의 6%만 담아 오던 문제**를 고칩니다. 기본 서비스 포트는 계속 `4747`이며 기존 API·MCP 호환성을 유지합니다.

## 수정

### 답을 자를 때 예산 대부분을 버렸습니다

- 답은 읽는 쪽이 이음매를 볼 수 있는 곳에서 잘립니다 — 섹션 시작, 문단, 줄 순서로. 섹션 규칙에는 "그렇게 잘라도 대부분이 남는가" 라는 조건이 있었지만 **문단·줄 규칙에는 없었습니다.**
- 처음 몇 줄 뒤로 빈 줄이 없는 파일 — 압축된 번들, CSV, 촘촘한 소스 — 은 **마지막 빈 줄이 내용이 시작되기 직전**에 있습니다. 거기서 자르면 머리말만 남습니다.
- 실측: `read-file` 에 `maxBytes: 12000` 을 주면 **682바이트**가 돌아왔습니다. 예산의 6%이고, 공지는 "이 도구의 12,000바이트 예산에 맞춰 잘랐다" 고 말합니다. 3,000·5,000·8,000 어느 예산을 줘도 같은 682바이트였습니다.
- 이제 모든 후보 경계가 같은 조건을 통과해야 합니다. 실측 사용률 **95~99%** 로 바뀌었습니다.

### 잘린 자리가 코드 펜스 안이면 그 뒤가 전부 코드로 읽혔습니다

- 줄 경계에서 자르면 열린 코드 펜스 안에서 끝날 수 있습니다. 그러면 **잘렸다는 공지와 Notes 가 파일 내용의 일부로** 렌더링됩니다.
- 펜스가 열린 채로 끝나면 닫습니다.

## 검증

- 빈 줄이 없는 촘촘한 파일을 여러 예산으로 자르며, 예산의 60% 이상을 담는지·UTF-8 이 유효한지·펜스가 닫히는지·잘렸다고 말하는지·Notes 가 남는지 확인
- 결과 섹션으로 이루어진 답은 **여전히 온전한 섹션에서 끝나는지** 확인 — 마지막 결과가 잘리지 않아야 한다는 기존 성질입니다
- 수정을 되돌리면 세 예산 모두 366바이트로 실패합니다
- FTS5 빌드·태그 없는 빌드·PostgreSQL 3가지 조합 전체 단위·통합·race 테스트, 빌드 모드 교차 시험

## 업그레이드 참고

- 마이그레이션이나 재색인은 필요하지 않습니다.
- 예산에 걸리던 답이 이전보다 훨씬 많은 내용을 담습니다. 예산 자체는 바뀌지 않습니다.
