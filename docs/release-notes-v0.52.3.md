# git-ctx v0.52.3

이번 릴리스는 v0.52.0에서 도입한 의존성 인벤토리의 **정확성 결함 2건**을 고칩니다. 기본 서비스 포트는 계속 `4747`이며 기존 API·MCP 호환성을 유지합니다.

## 수정

- **증분 색인이 인벤토리를 지우던 문제.** 증분 동기화는 변경된 파일만 전달받는데, 인벤토리를 ref 단위로 통째로 교체하고 있었습니다. 그래서 매니페스트를 건드리지 않은 커밋 하나만 들어와도 그 저장소의 의존성 기록이 전부 삭제되고, 전체 재색인 전까지 **"이 라이브러리를 쓰는 저장소가 없다"** 는 잘못된 답이 나왔습니다. 이제 증분 실행은 이번에 실제로 읽은 매니페스트와 삭제된 매니페스트의 행만 교체하고, 손대지 않은 매니페스트는 그대로 둡니다.
- **패키지 이름의 와일드카드가 패턴으로 해석되던 문제.** `%` 로 조회하면 카탈로그 전체가 그 패키지를 쓰는 것으로 보고되고 `_` 는 이름을 한 글자 넓혔습니다. 패키지 이름은 패턴이 아니라 식별자이므로 SQL 와일드카드를 이스케이프해 문자 그대로 취급합니다. 보안 공지 판정에서 자신 있게 틀린 답이 나오는 경로였습니다.

## 업그레이드 참고

- 마이그레이션은 필요하지 않습니다.
- v0.52.0~v0.52.2에서 **증분 색인이 한 번이라도 돈 저장소는 인벤토리가 비어 있을 수 있습니다.** 해당 저장소를 재색인하면 복구됩니다. 소스·색인 화면의 의존성 인벤토리 카드에 표시되는 커버리지(매니페스트 색인 저장소 수)로 확인하세요.

## 오프라인 Docker 이미지

릴리스 자산은 아키텍처 접미사가 없는 다음 두 파일입니다.

- `git-ctx-v0.52.3.tar.gz`
- `git-ctx-v0.52.3.tar.gz.sha256`

```bash
sha256sum -c git-ctx-v0.52.3.tar.gz.sha256
gzip -dc git-ctx-v0.52.3.tar.gz | docker load
docker image inspect git-ctx:v0.52.3 --format '{{.Os}}/{{.Architecture}} {{.Config.User}}'
```

기대 결과는 `linux/amd64 10001`입니다. 아카이브에는 `git-ctx:v0.52.3`과 `git-ctx:0.52.3` 태그가 포함됩니다.

## 검증

- Go 전체 단위·통합·race 테스트, vet와 build
- 증분 색인 회귀 시험: 비매니페스트 커밋 후 인벤토리 보존, 매니페스트 1건 변경 시 해당 행만 교체, 삭제된 매니페스트 행 제거
- 와일드카드 회귀 시험: `%`·`_`·`%log4j%` 는 0건, 점·콜론이 들어간 정상 이름은 정상 조회
- 관리자·사용자 UI JavaScript 구문 및 계약 시험
