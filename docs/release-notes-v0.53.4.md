# git-ctx v0.53.4

이번 릴리스는 실제 인스턴스를 띄워 확인한 **연결 누락**을 고칩니다. 기본 서비스 포트는 계속 `4747`이며 기존 API·MCP 호환성을 유지합니다.

## 수정

- **웹훅 수신 현황과 의존성 인벤토리 화면이 항상 비어 있었습니다.** 두 API 핸들러는 구현·문서화되어 있고 콘솔도 호출하고 있었지만 라우터에 등록되지 않아, 모든 요청이 404 로 끝났습니다. 이제 `GET /api/v1/admin/webhook-events` 와 `GET /api/v1/admin/dependency-inventory` 가 문서대로 응답합니다.
- **같은 저장소가 자기 자신과 버전이 다르다고 집계되고 있었습니다.** 카탈로그 인벤토리가 `^18.2.0` 선언과 그것을 고정한 락파일의 `18.3.1` 을 서로 다른 버전으로 세어, 표준화 대상이 아닌 저장소를 “버전 분산”으로 올렸습니다. 이제 락파일이 있는 저장소는 해석된 버전 하나로만 집계하며, 그 사실을 진단 문구로 밝힙니다.
- 저장소 지도 시험 API 응답에 스택이 빠져 있었습니다. 콘솔에서 확인하는 내용이 에이전트가 실제로 받는 내용보다 적었습니다.

## 회귀 방지

- 공개된 OpenAPI 문서의 모든 경로가 실제로 라우팅되는지 확인하는 시험을 추가했습니다. 정적 화면이 `/` 에서 서비스되기 때문에 등록되지 않은 API 경로도 404 대신 화면 핸들러로 흘러가며, 이 시험은 그 경우를 실패로 판정합니다. 라우트를 지우고 실패를 확인해 두었습니다.
- 이미지 빌드 안에서도 전체 시험이 돌기 때문에, 빌드 컨텍스트에 API 명세 파일을 함께 넣어 같은 시험이 오프라인 이미지 경로에서도 동작하게 했습니다.

## 업그레이드 참고

- 마이그레이션이나 재색인은 필요하지 않습니다.
- 인벤토리의 “버전 분산” 개수는 이번 수정으로 줄어들 수 있습니다. 줄어든 만큼이 락파일로 설명되는 저장소입니다.

## 오프라인 Docker 이미지

릴리스 자산은 아키텍처 접미사가 없는 다음 두 파일입니다.

- `git-ctx-v0.53.4.tar.gz`
- `git-ctx-v0.53.4.tar.gz.sha256`

```bash
sha256sum -c git-ctx-v0.53.4.tar.gz.sha256
gzip -dc git-ctx-v0.53.4.tar.gz | docker load
docker image inspect git-ctx:v0.53.4 --format '{{.Os}}/{{.Architecture}} {{.Config.User}}'
```

기대 결과는 `linux/amd64 10001`입니다. 아카이브에는 `git-ctx:v0.53.4`과 `git-ctx:0.53.4` 태그가 포함됩니다.
