# git-ctx v0.60.1

이번 릴리스는 **드문 단어 검색이 전체 훑기 비용을 내던 것**을 없앱니다. 기본 서비스 포트는 계속 `4747`이며 기존 API·MCP 호환성을 유지합니다.

## 수정

- 전문 인덱스는 단어와 접두사를 찾습니다. 그것이 대체한 훑기는 **단어 안쪽**도 찾았습니다 — `invoice` 로 `settleInvoice` 를 찾는 경우입니다. 그 회수율을 지키려고, 인덱스가 요청한 개수를 채우지 못하면 항상 훑기를 덧붙이고 있었습니다.
- 그래서 **일치가 한 건뿐인 드문 단어**가 카탈로그 전체를 훑는 비용을 냈습니다. 청크 200,000개에서 357ms — 답은 6ms 면 나오는데 나머지는 "혹시 더 있을까"에 쓰였습니다.
- 이제 훑기는 **인덱스가 아무것도 찾지 못했을 때만** 돕니다. 그때는 훑기가 유일한 경로이고, `invoice`/`settleInvoice` 경우가 정확히 그렇습니다. 인덱스가 이미 찾았다면 답이 짧더라도 훑지 않고, **그 사실을 답에 밝힙니다** — 긴 이름 안쪽까지는 찾지 않았으니 그 이름으로 직접 검색하라고.

## 실측 (저장소 400 · 청크 200,000)

```text
드물지만 존재하는 단어    357ms → 6ms
없는 단어                194ms  (변화 없음, 훑기가 유일한 경로)
흔한 두 단어              58ms  (변화 없음)
```

## 개선

- 두 가지 다른 사실을 하나의 경고로 합쳐 쓰던 것을 나눴습니다.
  - 읽기 상한에 걸렸다 → “앞의 N건만 읽었으니 표본입니다”
  - 안쪽 검색을 생략했다 → “단어로 찾았고, 긴 이름 안쪽은 찾지 않았습니다”
  - 이전에는 상한에 걸리지 않았는데도 표본이라고 말하는 경우가 있었습니다.

## 검증

- 상한 도달·안쪽 생략 각각의 문구 시험, 인덱스 없는 빌드에서는 생략 자체가 없음을 확인
- FTS5 빌드·태그 없는 빌드 양쪽 전체 단위·통합·race 테스트
- 20만 청크 인스턴스에서 위 수치 실측

## 업그레이드 참고

- 마이그레이션이나 재색인은 필요하지 않습니다.
- 답이 짧을 때 “긴 이름 안쪽은 찾지 않았다”는 문구가 새로 붙습니다. 그 이름으로 직접 검색하면 이전과 같은 결과를 얻습니다.
