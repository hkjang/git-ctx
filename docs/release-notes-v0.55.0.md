# git-ctx v0.55.0

이번 릴리스는 **선언된 소유자(CODEOWNERS)** 를 답에 넣고, **색인 정책 변경이 실제로 적용되도록** 만듭니다. 기본 서비스 포트는 계속 `4747`이며 기존 API·MCP 호환성을 유지합니다.

## 개선

- **`find-code-owner` 가 CODEOWNERS 선언을 먼저 답합니다.** 지금까지는 커밋 이력만으로 “누가 이 코드를 아는가”를 추정했습니다. 그건 대리 지표입니다 — 최근에 바빴던 사람을 가리킬 뿐, 책임자를 가리키지 않습니다. 저장소가 CODEOWNERS 로 이미 답을 적어 두었다면 그 답이 먼저 나오고, 어떤 규칙이 매칭됐는지와 그 규칙이 덮은 규칙까지 보여줍니다. 커밋 기반 순위는 그 아래에 근거로 남습니다.
- 선언은 색인된 내용에서 읽으므로 **소스 서버에 닿지 못해도 답합니다.** 커밋 이력을 읽지 못한 경우에는 그 사실을 함께 밝힙니다.
- `CODEOWNERS`, `.gitlab/CODEOWNERS`, `docs/CODEOWNERS`, `.github/CODEOWNERS` 를 순서대로 찾고, gitignore 문법(`/` 고정, 디렉터리, `*`, `**`)과 GitLab 섹션·주석을 해석하며, **마지막에 매칭된 규칙이 우선**합니다.

## 수정

- **색인 정책을 바꿔도 아무 일도 일어나지 않았습니다.** ref 의 커밋이 움직이지 않으면 재색인은 “완료, 0건”으로 끝났고, 새로 포함한 확장자는 다음 push 가 있을 때까지 색인되지 않았습니다. 이제 저장된 내용이 어떤 정책으로 만들어졌는지를 ref 마다 기록하고, 정책이 바뀌면 커밋이 그대로여도 다시 읽습니다.
- 정책을 저장하면 색인된 모든 ref 에 대해 재색인 작업을 만들고, 어떤 ref 가 큐에 들어갔는지 응답과 화면에 표시합니다. 콘솔은 더 이상 별도의 재색인 작업을 중복 생성하지 않습니다.
- 업그레이드 시 전체 저장소를 다시 읽지 않도록, 기록이 없는 ref 는 “현재 정책”으로 간주합니다. 정책을 실제로 바꾼 저장소만 다시 읽습니다.

## 검증

- 실제 인스턴스에서 정책 저장 → ref 재색인(7건) → 새로 포함된 `CODEOWNERS` 색인 → `find-code-owner` 가 `/config/` 는 `@ops-team, @alice`, `*.go` 는 `@backend-team`, 나머지는 `@platform-team` 으로 답하는 것까지 확인
- CODEOWNERS 패턴 14종 회귀 시험, 섹션·주석 파싱, 소스 서버 없이 선언만으로 답하는 경로 시험
- 정책 변경 시 같은 커밋에서 재색인되는지, 정책을 좁히면 색인이 줄어드는지 시험(기록 비교를 되돌려 실패하는 것까지 확인)
- Go 전체 단위·통합·race 테스트, vet와 build, 콘솔 JavaScript 시험

## 업그레이드 참고

- 마이그레이션 `046_policy_revision.sql` 이 `repository_ref_states` 에 열을 추가합니다. 기존 행은 빈 값으로 남고, 그 상태는 재색인을 유발하지 않습니다.
- 정책을 저장하면 그 저장소의 색인된 ref 수만큼 작업이 생깁니다. 큰 저장소에서는 전체 재읽기이므로 시간이 걸립니다.
