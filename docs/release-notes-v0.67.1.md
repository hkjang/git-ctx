# git-ctx v0.67.1

이번 릴리스는 **복구 키 회전이 설치를 못 쓰게 만들던 문제**를 고치고, 지난 세 릴리스로 달라진 동작에 맞춰 운영 문서를 바로잡습니다. 기본 서비스 포트는 계속 `4747`이며 기존 API·MCP 호환성을 유지합니다.

## 수정

### 복구 키 회전이 설치를 열 수 없게 만들었습니다

- 키가 데이터베이스에 저장되면서, 저장된 키 자료는 **회전해서 버리려는 바로 그 키**로 감싸여 있습니다.
- 연결 문자열이 그대로일 때는 회전이 우연히 동작했습니다 — 예전 DSN 파생 값이 아직 유효한 대체 경로였기 때문입니다. **연결 문자열도 바뀐 뒤에는**(그것이 v0.66.0 이 가능하게 만든 바로 그 상황입니다) 회전이 기동하지 못하는 설치를 남겼습니다.
- 이제 `GIT_CTX_PREVIOUS_RECOVERY_KEY` 에 직전 키를 넣고 한 번 기동하면 저장된 키 자료가 새 키로 다시 감싸집니다. 직전 키 없이 기동하면 거부되며, 오류 문구가 이 변수를 안내합니다.
- **회전 전에 만든 백업 아카이브도 직전 키가 주어진 동안 열립니다.** 그러지 않으면 회전이 모든 백업을 조용히 못 쓰게 만듭니다 — 아무도 그날이 오기 전까지 알아차리지 못하는 종류의 손실입니다.

### 운영 문서가 더 이상 존재하지 않는 시스템을 설명하고 있었습니다

지난 세 릴리스가 `GIT_CTX_RECOVERY_KEY` 의 의미를 바꿨는데 문서는 그대로였습니다. 온프레미스 제품에서 틀린 운영 문서는 그 자체로 결함입니다.

- "설정 암호화 키와 API-key pepper 는 DSN 에서 도메인 분리해 결정" → 데이터베이스에 저장되고 복구 키로 감싸인다고 고쳤습니다.
- "최초 Bootstrap DSN 문자열은 ... 임의로 변경하지 않는다" → 이제 DSN 은 자유롭게 바꿀 수 있으며, v0.66.0 이전 설치는 **한 번은 원래 DSN 으로 기동**해야 한다고 적었습니다.
- 복구 키에 무엇이 달려 있는지(설정 키, 복구 토큰 서명, 백업 봉인), 백업 볼륨과 왜 분리해야 하는지 명시했습니다.
- 복구 키 회전 절차와 재해 복구 절차를 새로 적었습니다.
- 백업이 "DSN 파생 키" 로 암호화된다는 설명을 복구 키 기준으로 고치고, 아카이브가 키 자료를 함께 담아 다른 기기에서 복원된다는 사실을 적었습니다.

## 검증

- DSN 이 바뀐 뒤 직전 키와 함께 회전하고, 설정을 읽고, **회전 전 백업을 복원**하고, 그 뒤 새 키만으로 기동되고, 다음 회전은 다시 자기 직전 키를 요구하는지 회귀 시험
- FTS5 빌드·태그 없는 빌드·PostgreSQL 3가지 조합 전체 단위·통합·race 테스트, 빌드 모드 교차 시험, 릴리스 바이너리 업그레이드 시험
- 문서 전수 검색으로 옛 설명이 남아 있지 않음을 확인

## 업그레이드 참고

- 마이그레이션이나 재색인은 필요하지 않습니다.
- `GIT_CTX_PREVIOUS_RECOVERY_KEY` 는 선택 사항이며 회전 중에만 필요합니다. 회전이 끝나면 제거하십시오.
