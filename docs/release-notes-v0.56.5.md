# git-ctx v0.56.5

이번 릴리스는 **동시 부하와 백업·복원 동작을 규모에서 실증**하고, 그 특성을 회귀 시험으로 고정합니다. 코드 동작 변경은 없습니다. 기본 서비스 포트는 계속 `4747`이며 기존 API·MCP 호환성을 유지합니다.

## 실증 (저장소 400 · 청크 200,000)

**동시 호출**

```text
동시 1   호출 6건    p50 5~58ms
동시 8   호출 40건   p50 55~105ms · p95 ≤ 117ms · 113 call/s · 오류 0건
```

**백업이 도는 동안의 동시 호출** — SQLite 는 연결을 하나만 쓰므로, 오래 붙잡는 작업이 있으면 플랫폼 전체가 멈춥니다. 모든 테이블을 읽는 백업이 그 중 가장 긴 읽기입니다.

```text
백업 15.6s 진행 중 · 동시 4 · 호출 32건 · p95 ≤ 159ms · 68 call/s · 오류 0건
```

**백업·복원 왕복**

- 청크 20만 건 백업(30.8MB) → 절반 삭제 → 복원 → 20만 건 복구 확인
- 복원된 청크가 전문 인덱스에도 반영되는지 확인(트리거 경로). 인덱스는 백업에 실리지 않고 복원 시 다시 채워집니다.
- 복원은 세션을 무효화하며, 최초 관리자 자격으로 만든 키도 함께 만료됩니다.

## 추가

- 백업이 도는 동안 검색 20건이 모두 완료되는지 확인하는 회귀 시험을 넣었습니다. v0.56.3 에서 고친 두 건(설정 재조회, 벡터 동기화)이 정확히 이 유형이었고, 연결을 오래 붙잡는 변경이 다시 들어오면 이 시험이 잡습니다.

## 검증

- FTS5 빌드·태그 없는 빌드 양쪽 전체 단위·통합·race 테스트
- 규모 인스턴스에서 위 수치 실측

## 업그레이드 참고

- 마이그레이션이나 재색인은 필요하지 않습니다.
