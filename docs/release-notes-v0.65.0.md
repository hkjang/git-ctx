# git-ctx v0.65.0

이번 릴리스는 **이 플랫폼이 저장해 놓고 아무도 검색하지 않던 텍스트**를 찾을 수 있게 합니다. 기본 서비스 포트는 계속 `4747`이며 기존 API·MCP 호환성을 유지합니다.

## 수정

### 제목에만 있는 단어를 찾지 못했습니다

- 전문 인덱스는 **경로·제목·내용** 세 컬럼을 색인합니다. 인덱스가 없을 때 쓰는 훑기 조건도 셋 다 읽습니다. 그런데 행에 점수를 매기는 단계는 **경로와 내용만** 읽었습니다.
- 그래서 인덱스가 제목으로 찾아낸 청크가 점수 0을 받고 버려졌습니다. `## Settlement` 섹션이 있는 README 에서 `settlement` 를 검색하면 **인덱스는 1건을 찾고 답은 0건**이었습니다.
- 제목은 문서가 무엇에 대한 것인지 말하는 자리입니다 — `## Rollback procedure`, `## Settlement`. 런북에서 가장 먼저 찾게 되는 단어들입니다.
- 이제 제목도 점수에 들어갑니다. 제목으로 매치된 섹션은 **스니펫에 제목을 함께 보여 줍니다** — 그러지 않으면 답에 검색어가 한 번도 나오지 않습니다.

### 함수 위 주석을 저장해 놓고 검색하지 않았습니다

- 파서가 함수 위 doc 주석을 추출하고, 색인기가 저장하고, `find-symbol` 이 출력합니다. 그런데 **아무것도 그 안을 들여다보지 않았습니다.**
- `// Handle reconciles one order.` 의 `reconciles` 로 검색하면 심볼도 코드도 나오지 않았습니다.
- `find-symbol` 이 이제 documentation 도 검색합니다.
- 코드 청크가 **선언이 아니라 그 위 주석에서 시작합니다.** 청크의 첫 줄 번호도 함께 옮겨 가므로 줄 번호는 여전히 그 텍스트를 가리킵니다. 명백한 주석 줄만, 끊김 없이 이어지는 동안만 세므로 위 선언을 삼키지 않습니다.
- 함수 위 주석은 대개 저장소 전체에서 그 함수에 대한 유일한 산문이고, 이름이 아니라 동작으로 찾는 사람이 입력하는 것입니다.

## 검증

- 청크가 인용하는 줄 번호가 실제 파일 위치와 맞는지 대조하다 발견했습니다. 코드 청크는 맞았고(`ok`), 그 김에 던진 `search-code "Settlement"` 가 0건을 냈습니다.
- 제목에만 있는 단어·doc 주석에만 있는 단어가 각각 발견되는지, 청크 줄 번호가 주석 시작으로 옮겨 가는지 회귀 시험. 수정을 되돌리면 4건이 걸립니다.
- FTS5 빌드·태그 없는 빌드·PostgreSQL 3가지 조합 전체 단위·통합·race 테스트, 빌드 모드 교차 시험

## 업그레이드 참고

- 제목 검색과 `find-symbol` 의 documentation 검색은 **즉시** 적용됩니다. 이미 저장된 데이터를 읽는 것이라 재색인이 필요 없습니다.
- 코드 청크가 주석을 포함하는 것은 **해당 ref 가 다음에 색인될 때** 적용됩니다.
- 마이그레이션은 없습니다.

## 오프라인 Docker 이미지

릴리스 자산은 아키텍처 접미사가 없는 다음 두 파일입니다.

- `git-ctx-v0.65.0.tar.gz`
- `git-ctx-v0.65.0.tar.gz.sha256`

```bash
sha256sum -c git-ctx-v0.65.0.tar.gz.sha256
gzip -dc git-ctx-v0.65.0.tar.gz | docker load
docker image inspect git-ctx:v0.65.0 --format '{{.Os}}/{{.Architecture}} {{.Config.User}}'
```

기대 결과는 `linux/amd64 10001`입니다. 아카이브에는 `git-ctx:v0.65.0`과 `git-ctx:0.65.0` 태그가 포함됩니다.
