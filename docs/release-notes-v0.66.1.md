# git-ctx v0.66.1

이번 릴리스는 **SQLite → PostgreSQL 이전이 "성공"을 보고하고, 재시작하면 기동하지 못하는 데이터베이스를 남기던 문제**를 고칩니다. 기본 서비스 포트는 계속 `4747`이며 기존 API·MCP 호환성을 유지합니다.

## 수정

### 데이터베이스 이전이 열 수 없는 데이터베이스를 만들었습니다

- 논리 복사는 `system_settings` 와 `api_keys` 를 옮겼습니다. 그것들을 봉인하고 해싱한 **키는 옮기지 않았습니다** — 옮길 것이 없었기 때문입니다. v0.66.0 이전에는 키가 연결 문자열에서 파생되어 어디에도 존재하지 않았습니다.
- 대상은 자기 DSN 에서 다른 키를 파생하므로, 방금 받은 설정을 복호화하지 못하고 복사된 API 키는 전부 틀린 pepper 로 해싱된 상태가 됩니다.
- 엔드포인트는 **성공을 보고하고 재시작을 요청했으며, 그 재시작이 실패했습니다.**
- 이제 백업과 이전이 `platform_keys` 와 `platform_bootstrap` 을 함께 옮깁니다. 그것들은 `GIT_CTX_RECOVERY_KEY` 에서 파생한 키로 감싸여 있고 아카이브 자체가 암호화되므로, 아카이브가 이미 담고 있지 않던 비밀이 새로 들어가지는 않습니다.
- 이전 후 설정을 읽을 수 있고, **기존 API 키가 그대로 동작합니다.**

## 검증

- SQLite 에 설정과 API 키를 만들고, 제품이 제공하는 이전 엔드포인트로 PostgreSQL 로 옮기고, 엔드포인트가 요청한 대로 **재시작해서 설정을 읽고 그 API 키로 MCP 를 호출**하는 시험을 추가했습니다. 수정을 되돌리면 `platform_keys has 0 rows` 로 실패합니다.
- v0.66.0 이전에 쓰인 백업 아카이브(키 테이블이 없는)가 여전히 복원되는지 시험. 그 이전 세대(V1) 아카이브도 그대로 복원됩니다.
- FTS5 빌드·태그 없는 빌드·PostgreSQL 3가지 조합 전체 단위·통합·race 테스트, 빌드 모드 교차 시험, 릴리스 바이너리 업그레이드 시험

## 업그레이드 참고

- 마이그레이션이나 재색인은 필요하지 않습니다.
- 이 버전 이후로 만들어진 백업은 키 테이블을 포함합니다. 이전 버전에서 만든 백업도 그대로 복원됩니다.
- **이미 v0.66.0 이전에 PostgreSQL 로 이전했다가 기동에 실패한 경우**: 원래 SQLite 데이터베이스로 돌아가 이 버전으로 한 번 기동한 뒤(키가 기록됩니다) 이전을 다시 실행하십시오.
