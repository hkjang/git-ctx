# git-ctx v0.75.2

이번 릴리스는 **SQLite에서 외래 키가 재시작 후 꺼져 스키마의 모든 `ON DELETE CASCADE`가 무력화되던 문제**를 고칩니다. 기본 서비스 포트는 계속 `4747`이며 기존 API·MCP 호환성을 유지합니다.

> SQLite로 운영 중이라면 아래 "업그레이드 참고"의 무결성 점검을 한 번 실행하세요.

## 수정

### DSN에 파라미터가 없으면 데이터베이스가 자기 제약을 지키지 않았습니다

- SQLite는 **연결마다** 외래 키를 기본으로 끕니다. DSN이 켜지 않으면 스키마의 `ON DELETE CASCADE`가 전부 아무 일도 하지 않습니다.
  - 저장소를 지워도 권한·파일·청크·심볼이 남습니다.
  - 알림을 지워도 배달 기록이 남습니다. 보존 정책은 부모만 지우고 자식은 건드리지 않으므로 **영원히 남습니다.**
  - 존재하지 않는 부모를 가리키는 행의 삽입이 **성공합니다.**
- README는 파라미터가 포함된 DSN을 적어 두었지만, **아무것도 그것을 요구하지 않았습니다.** `file:/data/git-ctx.db`라고만 써도 플랫폼은 아무 불평 없이 기동합니다.

### 눈에 띄지 않은 이유: 일관되게 틀리지도 않았습니다

- `repositories` 테이블을 재구성하는 마이그레이션이 외래 키를 껐다가 켭니다. 그 `PRAGMA`는 **하나뿐인 풀 연결에 그대로 남습니다.**
- 그래서 파라미터가 빠진 설치는 **마이그레이션이 돈 기동에서는 제약을 지키고, 다음 재시작부터는 지키지 않았습니다.** 같은 설치가 시점에 따라 다르게 동작했고, 어느 쪽으로 돌고 있는지 아무것도 말해 주지 않았습니다.
- 시험이 재현하는 것이 바로 그 재시작입니다.

### 고친 방식

- SQLite DSN에 `_foreign_keys`와 `_busy_timeout`이 없으면 각각 `on`과 `5000`으로 채워서 엽니다.
- **운영자가 명시한 값은 그대로 둡니다** — 끄기로 한 선택도 포함해서. 기본값을 주는 것이 의도한 선택을 덮어쓰는 일이 되어서는 안 됩니다.

## 검증

- 파라미터가 없는 DSN, 명시한 DSN, 다른 파라미터만 있는 DSN 세 가지로 각각 **열고 → 닫고 → 다시 여는** 재시작 경로를 확인
- 재시작 후 `PRAGMA foreign_keys`가 켜져 있는지, 부모를 지웠을 때 자식이 함께 사라지는지, 없는 부모를 가리키는 삽입이 거부되는지 확인
- 기본값 채우기가 운영자 값을 덮어쓰지 않는지 5가지 DSN 형태로 확인 (`:memory:` 포함)
- 수정을 되돌리면 파라미터가 없는 두 DSN이 정확히 실패합니다
- FTS5 빌드·태그 없는 빌드·PostgreSQL 3가지 조합 전체 단위·통합·race 테스트, 빌드 모드 교차 시험, 릴리스 데이터베이스 업그레이드 시험, 콘솔 시험

## 업그레이드 참고

- 마이그레이션이나 재색인은 필요하지 않습니다. PostgreSQL 설치는 영향이 없습니다 — PostgreSQL은 언제나 외래 키를 강제합니다.
- **SQLite로 운영했고 DSN에 `_foreign_keys=on`이 없었다면, 이미 만들어진 고아 행이 남아 있을 수 있습니다.** 외래 키를 켜는 것은 기존 행을 검사하지 않습니다. 한 번 확인하세요.

  ```bash
  sqlite3 /path/to/git-ctx.db 'PRAGMA foreign_key_check;'
  ```

  출력이 없으면 깨끗합니다. 행이 나오면 각 줄이 `테이블 | rowid | 참조 대상 테이블 | 제약 번호` 형식이며, 해당 행을 지우면 됩니다.
