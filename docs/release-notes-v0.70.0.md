# git-ctx v0.70.0

이번 릴리스는 **저장소가 제한된 API 키가 읽으면 안 되는 저장소를 읽던 문제**를 고칩니다. 기본 서비스 포트는 계속 `4747`이며 기존 API·MCP 호환성을 유지합니다.

## 보안 수정

### 도구 두 개가 API 키의 저장소 제한을 우회했습니다

- API 키에는 읽을 수 있는 저장소 목록을 걸 수 있습니다. 대부분의 도구는 `libraryId` 인자를 검사하는 것으로 충분합니다 — 그 인자가 **필수**라 검사가 곧 필터이기 때문입니다.
- `find-runbook` 과 `build-context` 는 `libraryId` 가 **선택**입니다. 생략하면 저장소 전체를 훑습니다. 그런데 인자만 검사하고 **결과는 거르지 않았습니다.**
- 결과: 한 저장소로 제한된 키가 `libraryId` 를 그냥 빼고 부르면, **그 사용자가 볼 수 있는 모든 저장소의 런북 내용**을 읽을 수 있었습니다. `build-context` 는 교차 저장소 사용처를 모으므로 제한된 키에게 다른 저장소의 이름과 경로를 보여 줬습니다.
- `find-runbook` 은 결과를 거릅니다. `build-context` 는 허용 집합을 검색 계층까지 내려보내 대상 심볼·모호한 후보·교차 저장소 사용처 모두에 적용합니다 — 이 도구는 의도적으로 저장소 전체를 보므로 인자 검사로는 안전해질 수 없습니다.

## 검증

- **같은 내용을 키가 읽을 수 있는 저장소와 읽을 수 없는 저장소 양쪽에 넣고 모든 읽기 도구에 묻는** 시험을 추가했습니다.
- 누출이 없다는 결과가 공허하지 않도록, 각 도구를 **제한 없는 키로도** 부릅니다. 제한 없는 답에 금지된 저장소가 나타나지 않으면 그 도구는 경계를 시험하고 있지 않은 것이며, 시험은 조용히 통과하는 대신 그렇게 말합니다.
- 수정을 되돌리면 `find-runbook` 과 `build-context` 두 줄로 실패합니다.
- 나머지 제약도 전수 확인했습니다 — scope, 저장소 목록, CIDR, 분당 호출 수, 만료, 폐기, 비활성화 모두 강제됩니다.
- FTS5 빌드·태그 없는 빌드·PostgreSQL 3가지 조합 전체 단위·통합·race 테스트, 빌드 모드 교차 시험

## 업그레이드 참고

- 마이그레이션이나 재색인은 필요하지 않습니다.
- 저장소가 제한된 키를 쓰는 에이전트는 `find-runbook`·`build-context` 에서 **이전보다 적은 결과**를 받습니다. 이전에 받던 것이 받으면 안 되던 것입니다.
- 제한이 걸리지 않은 키는 영향이 없습니다.
