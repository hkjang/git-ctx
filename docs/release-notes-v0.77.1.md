# git-ctx v0.77.1

이번 릴리스는 **색인이 표현할 수 없는 검색어를 "일치 없음"으로만 답하던 문제**를 고칩니다. 기본 서비스 포트는 계속 `4747`이며 기존 API·MCP 호환성을 유지합니다.

## 수정

### "아래 메모를 확인하라"고 했는데 메모가 없었습니다

- `c++`를 검색하면 이렇게 답했습니다:

  ```
  ### Source Matches (0)
  No file contents matched. This is not the same as "the code does not exist": check the notes below.
  ```

  그런데 **`### Notes` 자체가 없었습니다.**
- C++ 코드가 들어 있는 저장소에서 `c++`를 검색하면 아무것도 나오지 않았습니다. 그리고 **아무것도 조회되지 않았습니다.** 색인은 단어를 저장하는데 `c++`에는 단어가 없어서 애초에 물어보지 않았고, 스캔도 돌지 않았습니다.

### 그리고 설명이 가장 필요한 순간에 버려졌습니다

- 색인 경로의 모든 주의 문구가 **"색인이 몇 건 보탰다"는 문장에 붙어** 있었습니다. 그래서 **보탠 것이 0건이면 설명도 함께 사라졌습니다.**
- 기존의 **"청크 2,000건까지만 훑었다"** 도 마찬가지였습니다 — 상한에 걸리고도 빈손이면 그 사실을 알 방법이 없었습니다.

### 고친 방식

- 색인은 이런 질의를 정말로 표현할 수 없습니다. **스캔은 할 수 있습니다** — 스캔은 텍스트를 찾고, 그 텍스트는 거기 있습니다.
- 쓸 만한 단어가 없는 질의는 **그 자체를 하나의 리터럴 검색어로** 씁니다. `c++`가 `parser.cpp`를 찾고, 답변이 **그렇게 했다고 말합니다.**
- 판정 조건은 "토큰이 없다"가 아니라 **"색인에 물어볼 수 없었다"**입니다. `--`는 토큰화가 유지해서 다른 경로로 같은 곳에 도착하기 때문입니다.
- **한 글자짜리 질의는 세 번째 사실**이고, 그것으로 따로 보고합니다.
- 색인이 답한 평범한 질의에는 이 문구들이 나오지 않습니다.

### 드라이버 일치 시험을 실제 카탈로그 형태로 넓혔습니다

- 이미지 태그, 패키지 이름, 차트 이름, API 경로 — 그리고 한쪽 질의 언어에서는 문법이고 다른 쪽에서는 텍스트인 모든 구두점 형태를 SQLite와 PostgreSQL 양쪽에서 비교합니다.
- **절반 이상이 아무것도 못 찾으면 실패합니다.** 아무것도 못 찾는 두 데이터베이스는 아무것도 일치하지 않습니다.

## 검증

- `c++`가 실제로 `src/native/parser.cpp`를 찾고, 답변이 색인에 물을 수 없었다고 말하는지 확인
- 아무것도 못 찾는 `a&b`에도 메모가 붙는지 확인 — 설명이 버려지던 바로 그 경우입니다
- 토큰화가 유지하는 `--`가 같은 방식으로 보고되는지 확인
- 한 글자 `x`가 "너무 짧다"로 따로 보고되는지 확인
- 색인이 답한 `settleInvoice`에는 이 문구가 **나오지 않는지** 확인
- 하이픈·경로·콜론 형태 15가지를 두 드라이버에서 비교해 같은 문서를 찾는지 확인
- 수정을 되돌리면 세 가지가 모두 빈 메모로 실패합니다
- FTS5 빌드·태그 없는 빌드·PostgreSQL 3가지 조합 전체 단위·통합·race 테스트, 빌드 모드 교차 시험, 릴리스 데이터베이스 업그레이드 시험, 콘솔 시험

## 업그레이드 참고

- 마이그레이션이나 재색인은 필요하지 않습니다. **질의 처리와 답변 문구만 바뀝니다.**
- 구두점만으로 이루어진 검색어가 이제 결과를 돌려줄 수 있습니다. 그런 검색은 색인 대신 스캔을 쓰므로 큰 카탈로그에서는 상한에 걸릴 수 있고, 그 사실도 답변에 나옵니다.
