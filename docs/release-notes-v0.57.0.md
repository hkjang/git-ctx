# git-ctx v0.57.0

이번 릴리스는 **임베딩·리랭커 경로를 실제 모델 서버와 함께 처음 끝까지 돌려** 확인하고, 거기서 드러난 두 가지를 고칩니다. 기본 서비스 포트는 계속 `4747`이며 기존 API·MCP 호환성을 유지합니다.

## 수정

- **`baseUrl` 에 `/v1` 을 넣으면 `/v1/v1/embeddings` 로 요청하고 있었습니다.** OpenAI 호환 공급자는 모두 base URL 을 `/v1` 로 끝나게 문서화하므로, 운영자는 그대로 붙여 넣습니다. 그러면 404 가 돌아오고 화면에는 “임베딩 엔드포인트를 사용할 수 없습니다”로 보입니다 — 장애와 구분되지 않고, 실제 원인인 중복된 경로는 어디에도 나타나지 않습니다. 이제 `https://host`, `https://host/v1`, `https://host/v1/embeddings` 를 모두 받아들입니다. 리랭커도 같습니다.
- **임베딩을 쓸 수 없고 색인에도 일치가 없을 때, 마지막 실패만 오류로 돌려주고 있었습니다.** 에이전트는 소스 서버 오류만 보고, 임베딩이 내려갔다는 사실도 색인을 이미 뒤졌다는 사실도 알지 못했습니다. 이제 시도한 경로를 모두 담습니다 — 임베딩을 왜 못 썼는지, 색인에 무엇이 없었는지, 실시간 질의가 어떻게 실패했는지.

## 실증 (모델 서버 연동)

결정적 벡터를 돌려주는 OpenAI 호환 서버를 세우고 실제 인스턴스에서 확인했습니다.

- 모델 설정을 저장하면 **재색인이 자동으로 걸리고** 청크 7건이 모두 임베딩됨(revision 기록, ref 상태 `ready`)
- `search-semantic` 이 질의를 실시간 임베딩해 유사도 순으로 응답(`retrieval: in-database scan`, similarity 0.24~0.73)
- 같은 질의 반복은 질의 벡터 캐시로 즉시 응답
- **모델 서버를 죽인 뒤**: 색인에 일치가 있으면 키워드 경로로 답하고 그 사실을 밝힘, 일치가 없으면 세 경로를 모두 담은 오류. 첫 호출은 재시도로 3초, 이후 회로 차단이 열려 4ms
- 색인·복원·ACL 은 이전 릴리스에서 확인한 대로 동작

## 검증

- URL 조합 7가지 경우 시험(중복 없음, 다른 위치의 `v1` 은 그대로)
- 임베딩 불가 + 색인 없음 + 소스 실패 시 오류 문구 시험, 색인에 있으면 결과를 버리지 않는지 시험
- FTS5 빌드·태그 없는 빌드 양쪽 전체 단위·통합·race 테스트

## 업그레이드 참고

- 마이그레이션이나 재색인은 필요하지 않습니다.
- `baseUrl` 을 `/v1` 없이 넣어 두고 동작하던 설치는 그대로 동작합니다. `/v1` 을 넣어 두고 404 를 겪던 설치는 이번 릴리스부터 동작합니다.
