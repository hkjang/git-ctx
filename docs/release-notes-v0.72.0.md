# git-ctx v0.72.0

이번 릴리스는 **끝나지 않는 소스 장애가 영원히 조용하던 문제**를 고칩니다. 기본 서비스 포트는 계속 `4747`이며 기존 API·MCP 호환성을 유지합니다.

## 수정

### 소스가 계속 실패하는 저장소를 아무도 알려 주지 않았습니다

- 색인 잡이 실패하면 지수 백오프로 다시 큐에 들어가고 시도 예산 5회를 씁니다. 다 쓰면 `failed` 가 되고 운영자에게 알림이 갑니다.
- 다만 **소스 장애는 일부러 예산을 쓰지 않습니다.** 서버가 재시작 중일 뿐인데 다섯 번 만에 저장소를 실패로 표시하는 것이 더 나쁘기 때문입니다. 옳은 설계입니다.
- 문제는 **장애가 끝나지 않는 경우가 고려되지 않았다**는 점입니다. API 가 계속 500 을 주는 저장소, 혹은 폐기된 토큰(401 도 장애로 분류됩니다)은 플랫폼이 도는 내내 **30초마다 재시도되고, `pending` 인 채로, 아무에게도 보고되지 않았습니다.**
- 그 저장소에 대한 답은 조용히 낡아 갑니다. 운영자 화면에서는 놀고 있는 큐와 구분되지 않습니다.
- 이제 잡이 **장애가 시작된 시각**을 기록합니다. 재시도는 그대로이고 예산도 여전히 쓰지 않습니다 — 서버가 죽었다고 저장소를 포기하는 것은 여전히 더 나쁩니다. 다만 장애가 **한 시간**을 넘기면 운영자에게 한 번 알립니다. 30초마다 재시도해도 알림은 저장소·ref 당 하나입니다.
- `list-index-jobs` 가 `Source failing since:` 로 함께 보여 줍니다.

## 검증

- 항상 실패하는 저장소를 큐 맨 앞에 두고 건강한 저장소 둘과 함께 돌려, **건강한 쪽이 굶지 않는지** 확인했습니다. 백오프가 없으면 하나의 고장난 저장소가 워커를 독점해 전체 색인을 멈춥니다.
- 재시도가 과거 시각으로 예약되지 않는지(즉 뜨거운 루프가 아닌지) 확인
- 재시작 길이의 장애는 보고하지 않고, 임계를 넘긴 장애는 보고하며, 반복 재시도가 알림을 반복 생성하지 않는지 시험
- FTS5 빌드·태그 없는 빌드·PostgreSQL 3가지 조합 전체 단위·통합·race 테스트, 빌드 모드 교차 시험, 릴리스 바이너리 업그레이드 시험

## 업그레이드 참고

- 마이그레이션 `051_index_job_outage.sql` 이 추가됩니다. 자동 적용됩니다.
- 재시도 동작은 바뀌지 않습니다. 오래 지속되는 장애에 알림이 하나 늘 뿐입니다.
