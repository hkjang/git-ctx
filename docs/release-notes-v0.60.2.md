# git-ctx v0.60.2

이번 릴리스는 **FTS5 태그 없이 빌드한 바이너리가 기존 데이터베이스를 열면 색인이 완전히 멈추던 문제**를 고칩니다. 기본 서비스 포트는 계속 `4747`이며 기존 API·MCP 호환성을 유지합니다.

## 수정

- 전문 검색 색인은 **트리거**로 유지됩니다. 트리거는 스키마에 남으므로 그것을 만든 바이너리보다 오래 삽니다. FTS5 모듈 없이 빌드한 바이너리가 그 데이터베이스를 열면, 실행할 수 없는 트리거를 물려받습니다.
- 실행할 수 없는 트리거는 자기를 부른 문장을 실패시킵니다. 그것이 `document_chunks` 에 대한 **모든 쓰기**입니다 — 색인이 통째로 멈추고, 오류 메시지는 운영자가 바꾼 적 없는 SQLite 모듈 이름을 말합니다.
- `go build ./...` 이 태그 없는 명령입니다. 플래그 하나 잊는 거리에 있었습니다.
- 게다가 그 상태에서 저장소는 **전문 검색이 된다고 보고**했습니다. `CREATE VIRTUAL TABLE IF NOT EXISTS` 는 이미 있는 테이블에 대해 모듈 없이도 성공하기 때문입니다. 이제는 색인에 **질문을 던져** 확인합니다.
- 모듈이 없으면 트리거를 내려놓아 데이터베이스를 다시 쓸 수 있게 만들고, **색인이 방치되었다는 사실을 적어 둡니다**. 다음에 모듈을 가진 빌드가 열면 그 기록을 보고 재구축합니다 — 외부 콘텐츠 색인은 자기가 낡았는지 스스로 알 수 없기 때문입니다.

## 개선

- ref 색인을 마칠 때 그 ref 의 모든 청크에 새 커밋을 찍습니다. 색인 대상 컬럼은 하나도 바뀌지 않는데, 트리거가 모든 컬럼에 반응하고 있어 **커밋 도장 한 번이 ref 전체를 다시 색인**했습니다.
- 트리거를 `AFTER UPDATE OF file_path,heading,content` 로 좁혔습니다. 청크 20,000개 기준 137ms → 56ms. 웹훅 푸시마다 드는 비용입니다.
- 기존 데이터베이스의 낡은 트리거도 교체됩니다 — `CREATE ... IF NOT EXISTS` 는 이미 있는 것을 그대로 두므로, 내려놓고 다시 만듭니다.

## 검증

- **두 바이너리가 같은 데이터베이스를 나눠 쓰는 시험**을 새로 추가했습니다(`test/store/build-mode.test.sh`). 태그 있는 빌드로 색인 → 태그 없는 빌드로 쓰기 → 다시 태그 있는 빌드로 검색까지 확인하며, CI 에서 매번 돕니다. 수정을 되돌리면 두 번째 단계에서 `insert=failed no such module: fts5` 로 실패합니다.
- 방치된 색인의 재구축, 커밋 도장이 텍스트를 다시 색인하지 않음, 텍스트가 실제로 바뀌면 여전히 반응함 — 각각 단위 시험
- FTS5 빌드·태그 없는 빌드 양쪽 전체 단위·통합·race 테스트

## 업그레이드 참고

- 마이그레이션 `047_index_maintenance.sql` 이 추가됩니다. 자동 적용됩니다.
- 태그 없는 빌드를 쓰다가 이 버전으로 올라오면 첫 기동에서 색인을 한 번 재구축합니다. 코퍼스 한 번 훑는 비용이고, 그 뒤로는 다시 트리거가 유지합니다.
