# git-ctx v0.72.1

이번 릴리스는 **매치가 없는 질의를 "플랫폼이 고장났다"고 답하던 문제**를 고칩니다. 기본 서비스 포트는 계속 `4747`이며 기존 API·MCP 호환성을 유지합니다.

## 수정

### query-docs 가 매치 없음을 실패로 보고했습니다

- `query-docs` 는 색인에 히트가 없으면 소스의 코드 검색 API 로 한 번 더 시도합니다. 그 대체 시도가 실패하면 **호출 전체를 오류로** 돌려줬습니다.
- 커넥터가 **아직 설정되지 않았거나 일시 정지된** 설치에서는, 표현이 색인과 맞지 않았을 뿐인 질의가 `isError: true` 로 돌아왔습니다. 에이전트는 도구가 고장난 줄 알고 재시도하거나 포기합니다 — 다르게 물어보는 대신에.
- 이제 그 경우를 정상 답변으로 돌려주고 **두 사실을 다 말합니다**: 색인에 매치가 없었다는 것과, 라이브 검색은 시도되지 않았고 그 이유가 무엇인지.
- **소스가 거절했거나 깨진 경우는 그대로 오류입니다.** 폐기된 토큰(401)이나 이 소스가 검색할 수 없는 ref 는 운영자가 고쳐야 할 문제이고, "매치 없음" 으로 뭉개면 고칠 것이 보이지 않습니다.

## 검증

- 저장소가 제공하는 k6 부하 스크립트는 CI 에서 돈 적이 없습니다. 그것이 주장하는 부하를 직접 걸어 확인했습니다 — `CONTEXT7_API_KEY` 헤더는 실재하고 동작합니다.
- 실측(청크가 있는 SQLite 설치, 도구 3종 반복):

```text
동시 1    처리량 131/s   search-code p50 10ms   p95 16ms
동시 50   처리량 151/s   search-code p50 378ms  p95 586ms
```

  지연은 늘지만 실패는 없고, 저장소가 걸어 둔 임계(p95 < 3s)를 크게 밑돕니다. 처리량이 동시성에 따라 늘지 않는 것은 SQLite 연결 풀이 하나로 직렬화되어 있기 때문이며, 이는 `SQLITE_BUSY` 를 막기 위한 의도된 선택입니다.
- 이 측정 중에 위 결함이 드러났습니다.
- 매치 없는 질의가 오류가 아니고, 이유를 함께 말하며, 매치가 있으면 여전히 답하는지 회귀 시험. 401 과 ref 미지원이 여전히 오류인지도 기존 시험으로 확인.
- FTS5 빌드·태그 없는 빌드·PostgreSQL 3가지 조합 전체 단위·통합·race 테스트, 빌드 모드 교차 시험

## 업그레이드 참고

- 마이그레이션이나 재색인은 필요하지 않습니다.
- 커넥터가 없는 설치에서 `query-docs` 가 오류 대신 답을 돌려줍니다. 오류로 분기하던 클라이언트가 있다면 확인이 필요합니다.
